# 统计口径

## 时间、身份和基础信息

以确认日期D、北京时间固定截止秒T为准。开始日均为00:00:00，当日=D，最近30天=D-29，近7天=D-6，过去90天=D-89。完整历史日结束为23:59:59；实时当天用明确的T。审计用 `time`，风险事件用 `alert_time`；服务端过滤后仍在本地校验上下界。

当前员工信息不代表历史快照。按 `employee_id` 去重，计数 `is_active is True` 得员工总数；`status=normal` 不等于激活。身份源计数用于核对目录，不代替激活人数。读取所有相关身份源，不自动选择第一个身份源。

风险员工数：最近30天所有等级风险事件中非空 `employee_id` 去重数。占比=风险员工数/已激活员工数；分母0显示不可计算，不伪装为0%。用户尚未要求风险员工同步按激活状态过滤，默认不加此限制；如需“已激活员工中的风险率”，先确认范围。

设备总数：终端列表返回的官方总数，不用日志中的活跃设备数替代。

姓名、部门优先官方员工目录。缺少员工ID的审计通过员工终端绑定的ID、名称、序列号、MAC反查。MAC先拆分并统一格式；冲突映射或多员工共用终端不能随意取一个。未解决身份不编造姓名，向用户说明影响，确认后处理；不默默丢失大小。部门使用当前目录，保留源部门路径，不发明组织。

## 当日和最近30天风险榜

1. 每个 `event_id` 只计一次；相同事件重复返回不是新上报。无ID、缺失/非法 `risk`、不合法时间等需要单独核查，不自动补零。
2. 低、中、高均纳入，不按 `level=high` 过滤。不排除名字含“测试”的策略。
3. 员工总分=该周期内所有上报事件 `risk` 相加。若同策略上报2次且各6分，贡献12分；与事件内部关联40次触发无关。
4. 按员工总分降序选TOP10。总分相同用上报条数降序，再以员工ID稳定排序。可能因此改变原TOP10人员，不能只对旧10人重排。
5. 按员工ID、**相同策略名称**合并。名称不同的“数量偏离基线”“大小偏离基线”分别一行，不因相似而合并。
6. 数据量=合并行里的上报事件条数，显示“2次”等；既不是 `hit_summary.count`，也不是 `logs_total` 或文件数。
7. 单次风险分一致时：`大量外发代码文件数量偏离基线（6分）`。同名策略确有多个分值时，保留一行并显示分值及对应上报数，如 `策略（8分×2次；6分×1次）`，不能伪称单一分值。
8. 同一员工明细按单次风险分降序；多分值组以最高分排序。同分用上报数降序、策略名稳定排序。
9. 姓名显示 `姓名\n（风险分：总分）`。按员工ID识别同一人，连续同人姓名单元格纵向合并，不能把同名不同人合并。部门、策略、数量仍独立保留。
10. 通道TOP5从当前员工当前策略的上报事件 `hit_summary.channels` 提取，每条上报对每个通道最多计1次，然后按上报条数降序。
11. 历史列：同一员工、同一策略在近7天/过去90天的**上报条数**，包括当前周期。沿用当前已确认的行为：不另按当前TOP5通道过滤。模板字段仍叫“相同通道行为数据”，不要悄悄改成普通DLP通道日志计数；需要改变这个定义时向用户确认。

## 文件外发放行TOP10

从最近30天全量审计日志分别切出当日/30天，再严格同时过滤：

```python
row['trigger'] == 'securityFileSend' and row['action'] == 'observe'
```

不包含 `codeUpload`、`codeDownload`、`securityFileBlock`；不以 `policy_action` 替代实际动作。日志ID去重；同文件在不同日志中重复外发分别累计，不按哈希或文件名去重。

按员工累加 `file_size` 字节数，降序选TOP10，同大小以员工ID稳定排序。不限制必须有风险事件，不默认要求员工已激活。缺少大小的日志不计入合计，**不是认为实际大小=0**；应保留缺失数量用于交付说明。全缺失不能生成“0字节健康榜单”。负数/非法大小应核查。

类型取 `file_parent_category`；字段缺失显示“日志未提供类型”，不自行推断扩展名。按该员工对应周期、上述放行日志的**已知大小**累加各类型字节数，按大小取TOP3。括号显示大小：`压缩文件（42.57 GiB）`。1024进制，依数值选择GiB/MiB/KiB/B，至少保留2位小数（字节整数）。员工总大小显示GiB，底层值保持数值。

校验：所有类型大小合计=员工大小合计；展示的前三类合计≤总大小。数据类型缺失但大小存在的仍应计入未知类型。大小未知的不能用于类型大小排名。

## 可执行辅助函数

`scripts/metrics.py` 使用标准库，不访问网络，不处理凭据：

- `risk_ranking(events, start, end, history_start, limit=10)`：输入逐页事件迭代器，流式聚合员工ID、总分、策略组、分值、上报数、通道和历史上报数；不需要把原始事件全集转为列表。
- `outbound_ranking(logs, start, end, terminal_map=None, limit=10)`：输入逐页审计迭代器，输出大小排名、类型TOP3和缺失诊断。两函数保留唯一ID用于重复检测，不在内存保留全量原始日志。
- `activated_count(employees)`：原始官方员工目录去重计数。

渲染层再从官方目录关联姓名/部门并填写模板。不要把当前客户的数据嵌入skill。执行 `python3 scripts/test_metrics.py` 可离线验证关键口径。
