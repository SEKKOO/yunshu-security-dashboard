# 模板与交付

## 模板优先级与边界

用户最新工作簿 > 本skill的 `assets/dashboard-template.xlsx`。附带模板源自用户最后调整的布局，已去除客户数据、姓名、分数、日期和日志内容，保留字段、格式、标题合并和填写区域。

先读取模板，识别区域再写入；有可用工具时预览模板。禁止依赖最初示例模板中的旧坐标。禁止把带客户数据的旧报告直接作为另一客户的新报告；清空整个数据区，包括合并单元格子区域和旧行尾。

默认一个Sheet1，不加新页，不改已有字段/顺序/配色/列宽；内容过长通过换行和合理行高显示。空间不足插入数据行，整个下方区域随之顺延，左右榜单保持同一段落起始行。原样保留底部图表字段文字但不填图表、不创建占位图表；用户明确要求再另行处理。

## 已确认布局

- B1:G1：合并的“信息安全运营看板”标题；H1是原日期字段，I1写实际截止时间及北京时间。
- 第二行：B2员工总数、C2值；D2风险员工、E2值；F2风险员工占比、G2公式；H2设备总数、I2值。**不要再写旧的B3/D3/F3/H3布局。**
- B4：当前日期和最近30天实际范围说明。
- 第一段B5“当日高危TOP10”，第6行字段；左侧B:G分别是姓名、部门、高危事件、数据量、主要通道TOP5、近7日相同通道行为数据。第7行起数据。
- 右侧K5说明“文件外发放行（已知大小合计）”；K:N分别姓名、部门、数据大小、数据类型TOP3。
- 第二段以B列“本月累计TOP10”定位，下一行为字段，再下一行为数据。G列历史字段是近3月；右侧仍为K:N。**行号随第一段所需行数变化，不硬编码30/31/32。**
- 原底部“月人均风险事件数量（折线图+柱状图）-维度：公司、部门”作为边界，不生成对应内容。

模板预留23条当日和45条月累计风险明细，是模板容量，不是强制榜单长度。各榜选最多10名员工，按策略分行可以超过10行；人数不足按实际显示，不能补假人。保留空白预留行或按用户要求收紧；扩展时复制相邻数据行的样式，勿复制其旧数值。

## 展示与合并

- 左侧姓名 `姓名\n（风险分：总分）`，同一员工相邻行纵向合并并垂直居中；不同周期不跨区域合并；相同名字不同ID不得合并。
- 事件名称 `策略名称（6分）`，不再显示“单次风险分：”；明细按单次分数降序，员工按风险总分降序。
- 数据量、历史上报数保持数值，格式 `#,##0" 次"`；不填触发次数。
- 外发员工大小为数值GiB，格式 `0.00" GiB"`；类型摘要示例 `压缩文件（42.57 GiB）`，逐类型换行。
- 原字段虽有“高危”“本月”“相同通道”等字样，按已确认统计口径填，不擅自改字段。交付时可简述实际口径，避免看板文字被误解。

## 工具与验证

风险/外发由 `scripts/generate.py` 调用 `scripts/render_workbook.py`，使用公开依赖openpyxl。`workbook_layout.py` 在API读取前检查模板边界。先暂存、重读核对数值/公式/合并，再原子发布。占比公式保留公式并写入经独立计算的缓存，不能声称执行了任意Excel公式。

软件清单由 `scripts/software_inventory.py --template ... --output ...` 调用同一Python写表模块。只修改确认的空白软件区域，不调用完整风险刷新入口。已有安装数据或未知区域时先确认，不静默清除。

校验：

1. 原字段/标题/样式保留；无旧姓名、旧日期、客户残留、凭据；公式分母为激活员工。
2. TOP10基于全体候选员工重新排序；所有等级参与；事件按ID计条数；总分等于展示策略对应分值×上报条数之和。
3. 历史列为同员工同策略7/90天上报条数，按实际边界。
4. 外发过滤是securityFileSend＋action observe；全类型字节数对账；TOP3按字节数排名、括号显示大小。
5. 导出后重读数值、公式缓存、合并区域、图表数量；有预览工具时检查变化区域显示；无预览工具时检查换行、行高、完整文本与合并，不以缺少预览作为阻断。

输出只交付最终 `.xlsx`，不默认附带原始员工目录、客户日志或构建脚本。报表与快照的实际截止时间应一致；仅重导出不伪称刷新。
