# 云枢信息安全运营看板

输出中文 `.xlsx` 看板，沿用用户提供的最新工作簿样式。没有新模板时使用 `assets/dashboard-template.xlsx`。客户名称不作为必填信息。

## 执行前确认

- **每次新的数据刷新前，向用户确认统计日期和本次 AK/SK。** 不从旧会话、缓存或 skill 中自动继承凭据。用户在本次执行中已提供的无需重复确认。纯样式修改、基于同一快照重算或重新导出，不要求重新提供凭据，不擅自刷新数据。
- 确认“当日”和截止时间；“本月累计”默认是包含当日的最近30天，近7日含当日，“近3月”指包含当日的过去90天。均使用 Asia/Shanghai。今天尚未结束时固定一次读取截止时间，不把它描述成全天数据。
- 先检查表格。字段、含义、映射或缺失数据处理存在问题时，**先向用户确认，再做依赖该答案的数据读取**；已确认的规则直接沿用。
- 只从用户授权的云枢服务地址读取，默认 `https://cs-hz0.sase.eagleyun.com`。凭据仅用于本次认证，不写入文件、输出、模板或日志。

## 工作流程

先确定本次范围：完整刷新风险/外发看板，或只补充软件安装清单。只补充软件时，阅读 [软件安装统计](references/software-installations.md)，不要执行下面的全量风险/外发刷新，不修改原看板数据或原更新日期。软件区单独标明采集时间。

1. 阅读 [数据接口与读取](references/data-reading.md) 和 [统计口径](references/metrics.md)。
2. 阅读 [执行与环境](references/execution.md)，使用统一入口 `scripts/generate.py`。先完成环境与模板预检，再用同一截止时间分页读取近90天风险事件、近30天审计日志、员工、身份源、绑定和设备总数。正常刷新使用新的运行目录；明确恢复同一次运行时才复用已验证的页面。
3. 核对分页完整性、唯一ID、时间范围；出现429时降速和有限退避。数据不完整时不作为正式报告交付。
4. 按统计口径计算。可复用 `scripts/metrics.py` 的纯函数；其输入契约见统计口径。不得把事件触发次数误作上报次数。
5. 阅读 [模板与交付](references/workbook.md)。统一入口调用附带 `scripts/render.mjs` 填充、合并、扩展模板，重读导出文件并校验后才发布；不再临时编写一套渲染器。不调用 HTML 报告生成器，不创建风险员工任务附件。
6. 核对员工总分、事件上报条数、排名、文件类型大小与员工大小合计，检查导出的合并、公式和渲染效果。
7. 保存到当前工作区的用户输出目录，保留源模板，提供最终 `.xlsx` 和实际截止时间。只有用户要求时才另出明细。

## 不可混淆的口径

- 员工总数：员工目录中 `is_active` 严格为布尔 `true` 的去重员工数。
- 风险：低、中、高所有等级均计；风险员工数是周期内所有风险事件去重员工数，不默认按激活状态过滤。
- 风险总分：每个事件ID计一次，累加事件 `risk`。等价于按分值分组后的“风险分 × 上报次数”。**不乘 `hit_summary.count` 或 `logs_total`。**
- 员工按风险总分降序重新选TOP10；同一员工同名策略合并，事件明细按单次风险分降序。保留模板原有“高危”标题，但统计不限制为高危。
- 外发大小：仅 `trigger == securityFileSend` 且实际 `action == observe`。不依据 `policy_action` 认定放行，不含代码上传、下载或拦截。
- 类型TOP3按类型累计字节数降序，括号里显示大小，不显示次数；大小缺失不计，未知类型保留明确标签。
- 默认不生成折线图、柱状图；不自行添加月人均风险图表或数据区。

用户后续明确变更口径时，以最新指令为准，更新相关计算、展示和校验，不沿用已被替代的旧规则。

软件清单的最新约定：用户指定的三类软件（Dassault Systemes Software Version、Dassault Systemes SIMULIA、Solidworks）按“安装即纳入”统计，不依赖平台盗版标识；所有匹配的软件名和版本都列出。该口径是用户定义的清单范围，不能泛化为平台逐台盗版鉴定。其他用户未指定软件或判定口径时先确认，不自动套用这三类。
